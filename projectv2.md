## 1. Project Overview

A production Learning Management System for **Instructional Graphics**:

- **Course catalog** — browse, search by category, filter
- **License keys** — single-use codes generated by Shopify webhook or admin bulk-create, redeemed by users to unlock paid courses
- **Free courses** — instant enroll path, no license needed
- **Course content** — modules → lessons (Video / Storyline / Text / Download) + quizzes
- **Quiz engine** — 9 question types, manual + auto grading, attempt history
- **Progress tracking** — per-lesson `LessonProgress` rolls up to per-course `Progress.completionPercent`
- **Certificate** — printable HTML cert at 100% completion
- **Multi-device session control** — JWT cookies + DB-backed sessions, per-user device limit enforced server-side
- **Admin panel** — courses, modules, lessons, quizzes, questions, answers (drag-drop reorder), users (ban/suspend/role), licenses, sessions, reports, quiz review
- **Storyline auto-advance** — iframe `postMessage` listener with 5-second countdown overlay (new feature, see §13)

| Surface | Domain |
|---|---|
| LMS web app | `lms.instructionalgraphics.org` |
| Storyline content (HTML iframes) | `courses.instructionalgraphics.org` |
| Source content (e.g., HLS m3u8) | `courses.instructionalgraphics.org` |

The split is intentional: course content (potentially many GB of media) sits on a static cPanel host, the LMS app sits on a Node hosting tier (Plesk + Phusion Passenger). The LMS proxies HLS through `/api/video-proxy` to keep everything same-origin in the browser.


Loads env, sets production default, hands off to `react-router-serve` CLI which spins up Express + the SSR bundle.

### 5.5 [`tsconfig.json`](tsconfig.json)

- `strict: true`
- `verbatimModuleSyntax: true` — requires explicit `import type {...}` for type-only imports
- Path alias: `~/*` → `./app/*` (also `vite-tsconfig-paths` resolves at runtime)
- Includes auto-generated React Router types under `.react-router/types/**/*`

### 5.6 [`Dockerfile`](Dockerfile)

Multi-stage build:

| Stage | Purpose |
|---|---|
| `build-deps` | `npm ci` (full install, including devDeps) |
| `build` | `npx prisma generate` + `npm run build` |
| `prod-deps` | `npm ci --omit=dev` |
| (final) | Copies prod node_modules, generated `.prisma/`, Prisma CLI, `build/`, `prisma/`, `package.json` |

Runtime command:
```sh
npx prisma db push --accept-data-loss && npm run start
```

> Note: `db push --accept-data-loss` is destructive in some scenarios. For long-lived production data, prefer `prisma migrate deploy` (a safer migration runner).

## 8. Authentication & Session Model

[`app/utils/auth.server.ts`](app/utils/auth.server.ts)

### 8.1 Configuration

| Const | Value |
|---|---|
| `JWT_SECRET` | `process.env.JWT_SECRET || "dev-secret-change-in-production"` |
| `COOKIE_NAME` | `"lms_session"` |
| `SESSION_DURATION_DAYS` | 7 |
| `COOKIE_SECURE` | `process.env.COOKIE_SECURE === "true"` |

### 8.2 Cookie Format

```
Set-Cookie: lms_session=<JWT>; HttpOnly; SameSite=Lax; Path=/; Max-Age=604800
```

`Secure` flag conditional on `COOKIE_SECURE` env. Default OFF (works behind HTTP proxies — set `true` in production behind HTTPS).

### 8.3 JWT Payload

```ts
{ userId: string; role: string; sessionId: string }
```

Signed with `JWT_SECRET`, expires after 7 days.

### 8.4 Session Lifecycle

```
Login → createSession() →
  1. Read User.maxDevices via $queryRaw
  2. Find active sessions ordered by lastActiveAt ASC
  3. If active count >= maxDevices: invalidate the oldest until under limit
  4. Generate sessionId UUID
  5. Sign JWT with sessionId embedded
  6. Insert UserSession row with SHA-256(jwt) as token (raw never stored)
  7. Return JWT for cookie
```

### 8.5 Session Validation (`getSessionUser`)

1. Extract JWT from cookie.
2. Verify signature with `verifyToken()`.
3. SHA-256 the JWT, look up `UserSession` by `id = payload.sessionId AND token = hash`.
4. Find row that is `isActive = true AND expiresAt > NOW()`.
5. Load user; reject if `isBanned || isSuspended`.
6. **Debounced** `lastActiveAt` update: only writes if >5 minutes since last update (fire-and-forget, ignores errors).

### 8.6 Helpers

| Function | Behavior |
|---|---|
| `hashPassword(pw)` / `verifyPassword(pw, hash)` | bcrypt 12 rounds |
| `signToken(payload)` / `verifyToken(token)` | JWT with 7d expiry; verify catches errors and returns `null` |
| `hashToken(jwt)` | SHA-256 hex |
| `createSessionCookie(token)` / `clearSessionCookie()` | `cookie.serialize` |
| `getDeviceInfo(request)` | `{ ipAddress, userAgent, deviceId }` (deviceId = SHA-256(`UA|IP`).slice(0,16)) |
| `createSession(userId, role, request)` | See §8.4 |
| `getSessionUser(request)` | See §8.5 |
| `invalidateSession(request)` | Sets `isActive = false` for the current session's token hash |
| `requireUser(request)` | Throws `redirect("/auth/login")` if no user |
| `requireAdmin(request)` | Throws `redirect("/student")` if `role !== "ADMIN"` |
| `generateLicenseKey()` | `LIC-XXXX-XXXX-XXXX` (36-char alphabet) |

### 8.7 Single-Device Enforcement

`User.maxDevices` controls concurrency:
- `maxDevices = 1` (default) — login invalidates the previous session
- `maxDevices = N` — the oldest `N - 1` sessions stay; older invalidated on overflow
- `maxDevices = 0` — unlimited (skip enforcement)

Enforcement is on **login**, not at validation time. Once a session passes the check it stays valid for 7 days regardless of subsequent logins on other devices (until pushed out by a future login).

### 9.4 Course Player (deep dive)

#### 9.4.1 URL Pattern

Active item is selected via search params, not path:
- `/student/course/:courseId?lesson=<lessonId>`
- `/student/course/:courseId?quiz=<quizId>`
- No param → first item

#### 9.4.2 Loader

`requireUser()`. Then in parallel:

1. `License` (status=ACTIVE for this course/user)
2. `Enrollment` for this course/user
3. `Course` with nested `modules → lessons` (both ordered by `order ASC`)

**Access control:** allow if any of:
- License found
- Enrollment found
- Course is `FREE` and `PUBLISHED`

Otherwise throws 403.

Then:

4. `Progress` upsert (sets `lastAccessedAt = now`)
5. `LessonProgress` for this user (just `lessonId` + `isCompleted`)
6. **Raw SQL** `Quiz` rows for modules in this course
7. **Raw SQL** `Question` rows for those quizzes (ordered by `order`)
8. **Raw SQL** `Answer` rows — `isCorrect` is **only exposed for `TRUE_FALSE` questions** (the player never reveals it for MC)
9. **Raw SQL** `QuizAttempt` rows for this user, latest first
10. Builds nested data: `quizzesWithData[]` (with questions, answers, latestAttempt), `quizzesModuleMap` (by moduleId).

#### 9.4.3 Item Sequencing

Builds `allItems[]` per module by interleaving lessons + quizzes sorted by `order`:

```ts
const allItems: Array<{ type: "lesson" | "quiz"; item: any; module: any }> = [];
for (const mod of course.modules) {
  const modLessons = mod.lessons.map(l => ({ type: "lesson", item: l, module: mod, order: l.order }));
  const modQuizzes = (quizzesModuleMap[mod.id] || []).map(q => ({ type: "quiz", item: q, module: mod, order: q.order }));
  const combined = [...modLessons, ...modQuizzes].sort((a, b) => a.order - b.order);
  for (const e of combined) allItems.push({ type: e.type, item: e.item, module: e.module });
}
```

Then computes:
- `currentIdx` — index of active item
- `prevItem` — `allItems[currentIdx - 1]` or null
- `nextItem` — `allItems[currentIdx + 1]` or null
- **`nextLessonItem`** — `allItems.slice(currentIdx + 1).find(i => i.type === "lesson")` — used by Storyline auto-advance to skip past quizzes (added in this branch)
- `totalLessons`, `totalDuration` (sum of `lesson.duration`), `totalItems`

#### 9.4.4 Action Intents

##### `intent=update_progress`

- Body: `percent` (0–100, clamped), `completed` ("true"/"false")

#### 9.7.1 [`shopify.webhook.tsx`](app/routes/shopify.webhook.tsx) — `/shopify/webhook`

- **Loader:** Health check `{ status: "Shopify webhook endpoint active" }`.
- **Action (POST only):**
  1. Read raw body (`request.text()`) + `X-Shopify-Hmac-Sha256` header.
  2. Verify with `verifyShopifyWebhook(rawBody, hmac)` (timing-safe). Returns 401 if invalid.
  3. Parse JSON. Extract `customerEmail` (from `order.email` or `order.customer.email`). Parse `lineItems`.
  4. For each line item: map `item.sku → courseId`. Look up `Course`. For each unit in `quantity`:
     - Generate unique key with `generateLicenseKey()`.
     - Insert `License` (status=`PENDING`, `shopifyOrderId`, `isBulk` flag based on quantity).
  5. `sendLicenseEmail()` to customer + `sendAdminOrderNotification()` to `ADMIN_EMAIL`.
  6. Return `{ ok: true, generated: count }`.
- **Idempotency:** Not enforced explicitly. Relies on Shopify's at-least-once delivery being benign (each retry generates new keys). For strict idempotency, would need to check `shopifyOrderId` uniqueness up front.

#### 9.7.2 [`api.video-proxy.ts`](app/routes/api.video-proxy.ts) — `/api/video-proxy`

- **Loader:** `?url=<encoded>` proxies an HLS stream segment. Optional `?debug=1` returns Node version.
- **Allowlist:** `ALLOWED_HOST = "courses.instructionalgraphics.org"`. URLs whose hostname differs return 403.
- **M3U8 rewriting:** detect playlist by URL `.m3u8` or content-type `mpegurl`. Split by lines:
  - Skip comments (`#` prefix) **except** `#EXT-X-KEY` (rewrites the `URI=...` to a proxy URL)
  - Non-comments → resolve to absolute URL → rewrite to `/api/video-proxy?url=<encodedAbsoluteUrl>`
  - Returns `application/vnd.apple.mpegurl` with `no-cache`
- **Direct fetch (TS segments / videos):**
  - Fetches upstream with 20s `AbortController` timeout, browser User-Agent, Referer header
  - Forwards client `Range` header (for seeking)
  - Streams `arrayBuffer` back with inferred MIME (`video/mp2t` for `.ts`, fallback `application/octet-stream`)
  - Forwards `Content-Range` header
  - Sets `Access-Control-Allow-Origin: *`
- **Auth:** None; hostname-restricted.

| `TRUE_FALSE` | Two answers, one correct | ✅ |
| `IMAGE_ANSWERING` | Pick from image options | ✅ |
| `VIDEO_ANSWERING` | Pick from video options | ✅ |
| `FILL_BLANK` | Free text, exact-match (case-insensitive) | ✅ |
| `MATCHING` | Drag pairs A→B | ✅ (full credit on submit) |
| `ORDERING` | Reorder items | ✅ (full credit on submit) |
| `SHORT_ANSWER` | Free text, manual graded | ❌ — admin grades in `/quiz-review` |
| `ESSAY` | Long form, manual graded | ❌ — admin grades in `/quiz-review` |

### 12.2 Grading Logic

(In the `intent=submit_quiz` branch of [`student.course.$courseId.tsx`](app/routes/student.course.$courseId.tsx).)

```ts
for each question {
  switch (questionType) {
    case MULTIPLE_CHOICE | TRUE_FALSE | IMAGE_ANSWERING | VIDEO_ANSWERING:
      isCorrect = submittedAnswerId && answers.some(a => a.id === submittedAnswerId && a.isCorrect)
      pointsEarned = isCorrect ? points : 0

    case FILL_BLANK:
      submitted = (formData[`answer_${q.id}`] ?? "").trim().toLowerCase()
      correctTexts = answers.filter(a => a.isCorrect).map(a => a.text.toLowerCase())
      isCorrect = correctTexts.includes(submitted)
      pointsEarned = isCorrect ? points : 0

    case ESSAY | SHORT_ANSWER:
      submittedText = formData[`answer_${q.id}`] ?? null
      isCorrect = null  // pending manual grading
      pointsEarned = 0

    default: // MATCHING, ORDERING
      pointsEarned = points  // full credit auto-awarded
      isCorrect = true
  }
}

isPassed = (score / maxScore * 100) >= passingGrade
```

### 12.3 Manual Grading Path

[`/quiz-review`](app/routes/quiz-review.tsx):
- Lists all `QuizAttemptAnswer` rows where `isCorrect IS NULL`
- Admin enters score (clamped 0–maxPoints)
- Updates the answer row + recomputes `QuizAttempt.score` and `isPassed`

### 12.4 Attempt History

`/student/quiz-history` shows the latest 100 attempts per user with full breakdown.

## 13. Storyline Auto-Advance Feature

(New in this branch — full spec at [latestupdate.md](latestupdate.md).)

### 13.1 Component

[`StorylinePlayer.tsx`](app/components/StorylinePlayer.tsx) — `forwardRef<HTMLIFrameElement, Props>`.

**Props:**

| Prop | Type | Notes |
|---|---|---|
| `src` | `string` | iframe URL (story.html) |
| `lessonId` | `string` | Tracking identifier |
| `nextLessonUrl` | `string \| null` | `null` disables auto-advance |
| `onComplete?` | `(lessonId) => void` | Called when iframe posts `lessonComplete` |
| `allowedOrigins?` | `string[]` | Extra hosts beyond auto-derived defaults |
| `title?`, `className?`, `allow?`, `sandbox?` | `string` | Forwarded to `<iframe>` |

### 13.2 Origin Allowlist (Hybrid)

The component builds an allowlist set:
1. **Auto-derives** `new URL(src).origin` (handles any admin-pasted host)
2. Falls back to `https://courses.instructionalgraphics.org`
3. Adds any custom origins via the `allowedOrigins` prop

Only `event.origin`s in this set are accepted.

### 13.3 Flow

1. Storyline last slide fires a `Timeline ends → Execute JavaScript` trigger:
   ```js
   window.parent.postMessage({
     action: 'lessonComplete',
     lessonPath: window.location.pathname.replace('/story.html', '').replace(/^\//, '')
   }, '*');
   ```
2. Component validates `event.origin` and `data.action === "lessonComplete"`.
3. Calls `onComplete(lessonId)` — wired in [`student.course.$courseId.tsx`](app/routes/student.course.$courseId.tsx) to the existing `markLessonComplete()` (which submits `intent=complete_lesson` via `useFetcher`).
4. If `nextLessonUrl` is non-null, sets `countdown = 5`.
5. Countdown ticker decrements every 1s. At 0, calls `navigate(nextLessonUrl)`.
6. **Continue Now** button: navigate immediately. **Stay Here** button: `setCountdown(null)` (cancel).
7. Cleanup on unmount: removes `message` listener.

### 13.4 Overlay Styling

```html
<div class="fixed bottom-8 right-8 z-[9999] animate-slide-in">
  <div class="bg-black/85 text-white px-7 py-5 rounded-xl shadow-2xl text-center min-w-[280px]">
    "Next lesson starting in..."
    <span class="text-5xl font-bold text-red-500 tabular-nums">{n}</span>
    <button class="bg-red-500 hover:bg-red-600">Continue Now →</button>
    <button class="bg-gray-700 hover:bg-gray-600">Stay Here</button>
  </div>
</div>
```

### 13.5 Why Skip Quizzes

`nextLessonItem` (computed in the loader) finds the next item of `type === "lesson"`. If the very next item is a quiz, `nextLessonUrl` is `null` so no countdown shows — auto-advancing into a quiz is jarring. Learners must navigate manually.

### 13.6 Forwarded Ref

Uses `forwardRef` so the parent's `iframeRef` still works for fullscreen toggle and "Restart Storyline" button.

## 14. HLS Video Streaming

### 14.1 Why a proxy?

Storyline content lives on `courses.instructionalgraphics.org`. The LMS app on `lms.instructionalgraphics.org` cannot directly play those m3u8 streams cross-origin without CORS headers (which the static host doesn't set). The proxy keeps everything same-origin from the browser's perspective.

### 14.2 Flow

```
<HlsPlayer src="/api/video-proxy?url=https://courses.../stream.m3u8" />
                 ↓
GET /api/video-proxy?url=...
                 ↓
hostname check: must match ALLOWED_HOST
                 ↓
fetch upstream m3u8
                 ↓
rewrite each segment URI → /api/video-proxy?url=<absolute>
                 ↓
return rewritten playlist
                 ↓
hls.js requests each rewritten segment URL
                 ↓
proxy fetches the .ts file and streams it back
```

`#EXT-X-KEY` URIs (HLS encryption keys) are also rewritten so DRM-style streams pass through correctly.

### 14.3 `resolveVideoEmbed()`

In [`student.course.$courseId.tsx`](app/routes/student.course.$courseId.tsx), the priority chain:
1. Full `<iframe>` HTML pasted by admin → extract `src`
2. YouTube URL → embed player
3. Vimeo URL → player
4. Wistia URL → embed iframe
5. URL ending in `.m3u8` → HLS via proxy
6. URL with video extension (`.mp4|.webm|.ogg|.mov|.avi|.mkv|.flv|.wmv`) → direct `<video>`
7. Anything else → generic iframe

## 15. Shopify Integration

### 15.1 Mapping

`Course.shopifyProductId` is set when admin links a Shopify product. The webhook then maps each line item by `item.sku === Course.shopifyProductId` (or by SKU equal to a course identifier — implementation uses `sku` field).

### 15.2 HMAC Verification

[`shopify.server.ts`](app/utils/shopify.server.ts):
- Reads `SHOPIFY_WEBHOOK_SECRET` from env
- HMAC-SHA256 of raw body, base64-encoded, compared via `crypto.timingSafeEqual`

### 15.3 License Generation

For each line item × quantity:
1. `generateLicenseKey()` → `LIC-XXXX-XXXX-XXXX` (uniqueness implicit via `License.key @unique`)
2. Insert `License` (status=`PENDING`, customerEmail from order, `shopifyOrderId` for audit, `isBulk` if quantity > 1)
3. Send customer email + admin notification

### 15.4 Idempotency Caveat

Currently no explicit dedupe by `shopifyOrderId`. If Shopify retries (network failure, slow response), additional licenses may be generated. Acceptable trade-off for now since:
- License keys are cheap
- Customer email gets multiple keys, but they only need one
- Admin can revoke duplicates manually

## 21. Security Notes

### 21.1 Content Security Policy

Set in [`root.tsx`](app/root.tsx#L17):

```
default-src 'self';
script-src 'self' 'unsafe-inline' 'unsafe-eval' https:;
style-src 'self' 'unsafe-inline' https:;
img-src 'self' data: blob: https:;
media-src 'self' blob: https:;
connect-src 'self' https:;
font-src 'self' https: data:;
frame-src 'self' https:;
```

> `'unsafe-eval'` is present mainly because Storyline runtimes use eval-like patterns and some hls.js builds touch eval. Tightening would require auditing the entire Storyline content set.

### 21.2 Authentication Hardening Already In Place

- bcrypt 12 rounds for passwords
- JWT signed with `JWT_SECRET` + 7-day expiry
- DB-backed session list — invalidating a row immediately blocks the JWT (server checks DB on every request)
- SHA-256 hash of JWT stored, never the raw token
- Single-device enforcement via `User.maxDevices`
- httpOnly + sameSite=Lax cookies, optional Secure

### 21.3 Cross-Origin Postmessage

[`StorylinePlayer.tsx`](app/components/StorylinePlayer.tsx) validates `event.origin` against an allowlist before trusting messages. Without this, any malicious tab could spoof `lessonComplete`.

### 21.4 Shopify Webhook

HMAC-SHA256 verify with `crypto.timingSafeEqual`. Returns 401 on any failure. Order body is JSON-parsed only after HMAC passes.

### 21.5 Video Proxy Allowlist

[`api.video-proxy.ts`](app/routes/api.video-proxy.ts) restricts to `courses.instructionalgraphics.org`. Without this, the proxy could be abused as an open SSRF (server-side request forger).

### 21.6 Items to Tighten Later

- **Webhook idempotency** by `shopifyOrderId`
- **Tighter iframe sandbox** — current `allow-scripts allow-same-origin allow-popups allow-forms allow-modals` is permissive
- **Production origin lockdown** — Storyline's `postMessage(..., '*')` should become `postMessage(..., 'https://lms.instructionalgraphics.org')` once stable
- **CSP nonces** — replace `'unsafe-inline'` with per-request nonces
- **Rate limiting** — none on login/register/forgot-password endpoints
- **`db push --accept-data-loss`** in Docker `CMD` — replace with `migrate deploy` for long-lived data
